# Phase 4 Report — Governed Hybrid RAG

Date: 2026-09-25

## Status

**VALIDATED**

Phase 4 delivers a working governed RAG demo with PostgreSQL, pgvector,
hybrid retrieval, document authority resolution, Claude answer generation,
and LLM-as-a-Judge evaluation.

## Implemented

- PostgreSQL registry for logical documents and versions
- deny-by-default document ACL table
- chunk store with PostgreSQL Full-Text Search
- pgvector embeddings using `VECTOR(1536)`
- HNSW cosine index
- lexical + semantic candidate generation
- Reciprocal Rank Fusion (RRF)
- semantic relevance guardrail currently calibrated at `>= 0.50`
- authority resolution using authority level and dates
- Claude grounded response generation
- LLM-as-a-Judge with relevance, faithfulness, completeness and conflict awareness
- deterministic business shortcut scripts
- CI with pytest, Ruff and mypy

## Security

The SQL retrieval path filters ACLs before lexical/vector ranking.

The authority-resolution path and document shortcuts were hardened during the
repository audit so they remain inside the caller's ACL scope.

The Python authorization engine already supports:

```text
ACL -> RBAC -> ABAC
```

The current interactive Phase 4 SQL demo directly enforces ACLs. RBAC and ABAC
exist in the deterministic authorization engine but are not yet wired into the
interactive SQL retrieval path.

Claude, the Jev-compatible decision adapter and the LLM-as-a-Judge never make
ALLOW/DENY decisions.

## Jev scope

The current implementation is a deterministic local adapter compatible with the
planned Jev decision contract. It is not yet a live external Jev API call.
